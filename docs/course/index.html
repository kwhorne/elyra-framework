Freddy Learning Elyra Framework

Freddy has a notes app on the web, built with Laravel and Svelte. In seventeen chapters he builds its desktop half with Elyra Framework 0.49: a compiled app with its own database, then the same app signed in to his Laravel backend, following the web, working offline and showing Laravel's notifications.

The course follows one app from rata new to a release. Each chapter names the guide pages it is built on, so you can always read the whole story there.

The chapters

  1. 1. Why a desktop app at all — What Elyra Framework is, the Laravel map, and one honest note before we start.
  2. 2. rata new and the first window — Getting rata, scaffolding a project, and what each file is for.
  3. 3. Commands: Rust that the page can call — #[command], the Ctx, Result and kinds of failure, rata codegen, cancellation and gating.
  4. 4. The container, providers, middleware and events — Bindings and Ctx, providers' two phases, middleware around every command, and two kinds of events.
  5. 5. A database on the desktop — One Database for SQLite, MySQL and Postgres, migrations and the schema builder, and #[derive(Model)].
  6. 6. make:resource, and validation all the way to the form — Generating a whole slice from a model, the registries, abilities, and errors that land under their field.
  7. 7. Live queries: lists that update themselves — #[command(live)], how Elyra decides what to re-run, the live.* stores, and when not to.
  8. 8. Being a real desktop app — Windows, the menu, the tray, global shortcuts, one instance with deep links, autostart, dialogs and the clipboard.
  9. 9. Settings, secrets and work in the background — The settings store, the keychain, a jailed storage disk, the cache, the queue and the scheduler.
  10. 10. AI in the app, and the app for AI agents — The AI SDK, and the app's commands as tools for AI agents over MCP, with confirmation.
  11. 11. Seeing the app while you build it — A coding agent that knows the framework and sees the running app, the inspector, one screen in several states, pointing at what to change, rata check, and the Theme Studio.
  12. 12. A Laravel backend — Backend and Http, the three Sanctum routes, Laravel's answers as kinds, signing in with the token in the keychain, and make:resource --backend.
  13. 13. Changes on the web, in the open windows — Listening to Laravel's broadcasting like Echo does, following a channel, and what each event does.
  14. 14. Working offline — The last answer per user, the outbox that sends each write once, the connection and outbox stores, and conflicts.
  15. 15. Laravel's notifications on the desktop — What $user->notify() sends, heard, shown, clicked, counted, listed and caught up, and rata make:notifications.
  16. 16. The app's own assistant — An assistant inside the app whose tools are its commands, held to the user's abilities, asking before what can't be undone, seeing the window it's asked from, and taking dictation.
  17. 17. Testing, bundling and the updater — TestApp and fakes, rata bundle and what it does not do, and updates that only install when their signature verifies.
